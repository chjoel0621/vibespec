# 사용자 맥락 생성 프로파일

## 목적

VibeSpec은 PRD, 기능 명세, IA, 유저 플로우를 하나의 SOT로 연결하는 플러그인이다. 기본 사용자는 혼자 제품을 구상·구현하는 메이커와 제품 기획자이며, 이후 팀이 같은 SOT를 검토·변경·병합할 수 있다.

따라서 생성기는 모든 제품을 사내 운영 시스템처럼 만들면 안 된다. 프로파일은 **같은 SOT 스키마 안에서 생성 어휘와 검토 관점을 정하는 일회성 판단**이다. SOT에 새 필드를 저장하지 않으며, 기존 제품 기획·추가 기획·변경 계획 계약도 바꾸지 않는다.

## 프로파일

| 프로파일 | 선택 기준 | 우선하는 경험 | 기본으로 넣지 않는 것 |
| --- | --- | --- | --- |
| `operations` | 조직 안에서 누가 어떤 책임으로 업무를 처리하는지가 핵심 | 접수, 배정, 상태, 승인, 예외, 권한, 감사 | 개인화·재방문을 억지로 넣지 않음 |
| `consumer` | 한 사람 또는 가족의 목표·기록·반복 행동이 핵심 | 첫 사용, 핵심 행동/기록, 진행 확인, 재방문, 개인화, 데이터 통제 | 담당자·우선순위·SLA, 승인 큐, SSO, 운영 대시보드, 감사 로그 |
| `marketplace` | 둘 이상의 참여자가 탐색·등록·응답·거래 또는 매칭·신뢰를 주고받음 | 참여자별 탐색과 행동, 상태 안내, 공개 범위, 신고·안전, 알림 | 내부 운영자를 주인공으로 한 승인 워크플로우 |

분류가 애매하면 모델이 추측하지 않고 "개인의 반복 사용 제품인가, 조직 운영 도구인가, 여러 참여자를 연결하는 장터인가"만 한 번 묻는다. 가족 공유, 신고, 관리자 존재만으로 `operations`를 고르지는 않는다.

## 생성 원칙

### Consumer

- 사용자 자신이 시작하고 끝내는 핵심 행동을 먼저 정의한다. 예: 기록, 체크인, 계획, 비교, 저장.
- 온보딩, 빈 상태, 진행 피드백, 재방문 이유를 제품 맥락에 맞게 연결한다.
- 알림·공유·외부 연동은 명시적 동의와 설정 변경 경로를 가진다.
- 내보내기·삭제·공개 범위는 데이터 성격상 필요한 경우 명시한다. 모든 개인 앱에 규제 도메인 비목표를 기계적으로 넣지 않는다.
- "운영자", "감사", "SLA"가 아니라 실제 사용자의 행동과 결과를 acceptance와 flow에 적는다.

### Marketplace

- 적어도 두 참여자 그룹을 PRD target에 명시한다.
- 각 참여자에게 발견/검색, 등록 또는 응답, 진행 상태 확인의 경로를 제공한다.
- 신고·검토·안전 조치는 허용한다. 다만 참여자에게 결과나 다음 단계를 보여 주며, 내부 처리 큐가 제품의 주 흐름을 대체하지 않는다.
- 프로필과 공개 범위, 저장 검색·알림 같은 재방문 장치를 맥락에 맞게 선택한다.

### Operations

- 담당자, 기한, 우선순위, 승인, 예외, 권한, 감사는 실제 업무 책임이나 통제 요구가 있을 때 구체적으로 쓴다.
- 소비자용 친밀한 습관·리마인더 흐름을 형식적으로 주입하지 않는다.

## 기획 밀도

요구사항·기능·상세기능의 개수는 제품 복잡도에 맞춘다. 개인 도구에 `6 requirements / 12 features / 24 subfeatures`를 무조건 채워 넣지 않는다. 그 수치는 풍부한 공개 템플릿을 만들 때의 목표치일 뿐, 플러그인의 일반 생성 최소 기준이 아니다.

모든 생성물은 다음을 만족해야 한다.

1. 핵심 사용자 행동과 그 결과가 requirement, IA, flow에 연결된다.
2. acceptance는 "정상 동작"이 아니라 관찰 가능한 상태·권한·결과를 말한다.
3. `inScope`와 `nonGoals`는 현재 전달 범위를 드러낸다.
4. `review-sot --profile <profile>`의 프로파일 경고를 해소하거나, 의도적 예외를 사용자에게 설명한다.
5. 구조 검증(`validate-sot`)과 내용 리뷰(`review-sot`)는 둘 다 실행한다.

## 적용 지점

- `SKILL.md`: 신규 생성 때 프로파일을 선택하고, 생성·검토 지침으로 사용한다.
- `review-sot.mjs`: consumer에 내부 운영 기본 어휘가 섞이는지, marketplace에 참여자 그룹이 부족한지 알리는 advisory review를 제공한다.
- 공개 템플릿 생성기: `operations`, `consumer`, `marketplace`를 명시적으로 넘긴다. 공개 템플릿은 더 깊을 수 있지만, 그 밀도를 일반 사용자 산출물의 강제 규칙으로 승격하지 않는다.

마케팅 문구의 독자·표현 규칙은 SOT 생성 프로파일과 별개다. 이 문서는 기획 데이터의 내용과 연결 품질만 다룬다.
