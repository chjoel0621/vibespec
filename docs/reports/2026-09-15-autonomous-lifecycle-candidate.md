# 사람 판단 전까지 진행한 lifecycle 후보 구현

기준일: 2026-09-15. 이전 A/B 기반 구현 위에 **선택적 변경 이력 계층**을
추가했다. 기존 SOT의 스키마와 JSON/HTML 호환성은 유지했다.

## 구현한 범위

| 영역 | 자동 동작 | 판단하지 않는 것 |
| --- | --- | --- |
| 기준선 | 등록 이후 전후 스냅샷·이유·변경 계획·digest 연결 보존 | 등록 이전 이력, 실제 배포 여부 |
| 영향·재검토 | 명시적 참조의 영향과 부모 변경 대상 표시, 이전 검사 stale 표시 | 자연어 정책의 완전한 영향 탐지 |
| 병합 | 실제 ID 매핑 및 PRD/semantic 잔여 검토 영속 보존 | 수동 검토를 완료했다고 추정 |
| 폐기·대체 | scope별 ID와 상세기능 인덱스의 재사용 거절, 이유·명시된 대체 관계 조회 | 대체 기능을 임의 선택 |
| 안전한 ID 배정 | 병합 시 과거 사용·폐기·미반영 semantic ID를 피해서 새 ID 배정 | 다른 기능에 폐기 ID 승계 |
| 저장·복구 | 불변 쓰기 계획, 완료 영수증, 파일별 교체, 인식 가능한 중단 복구 | 알 수 없는 외부 수정 덮어쓰기 |
| 동시 작업 | 저널 명령끼리 잠금, 종료된 로컬 소유자의 명시적 잠금 해제 | 다른 호스트·실행 중 프로세스 강제 종료 |

동작은 `init`, `status`, `capture`, `apply`, `rebase`, `merge`, `recover`,
`unlock`으로 제공한다. 쓰기는 기본 dry-run이며 `--apply`가 필요하다.
현재 파일과 이력이 일치하는 `current`와 사람의 검토 완료는 별개다.
제품 승인은 항상 `not-assessed`다.

## 검증 결과

실제 파일로 캠페인 동의·회의실 예약·CRM 내보내기 사례를 각각 실행했다.

| 항목 | 결과 |
| --- | --- |
| 관리되는 변경 | 3개 개념 × 5건 = 15건 저장 |
| 초기 등록을 포함한 이력 | 개념별 6개 레코드와 완료 영수증 |
| 여섯 번째 변경: 폐기 ID 재사용 | 3건 모두 거절, 원본·이력에 새 변경 미적용 |
| 병합 후 미검토 항목 | 개념별 7건 유지 |
| 전체 누적 검토 작업 | 개념별 20건 pending; 과거 기준의 작업 포함 |
| 관련 없는 요구사항 | 보존 |
| 제품 승인·사람 판정 | not-assessed / pending |

위 수치는 가상 시나리오의 엔진 결과다. 세 사례는 동일한 변경 패턴을
공유하며, 실제 운영 문제의 빈도나 사람 검토 효과를 증명하지 않는다.
누적 작업 20건은 서로 다른 실제 결함 20개를 뜻하지 않는다.

로컬 증거 패킷은 `outputs/vibespec-managed-lifecycle-2026-09-15/`에 있다.
도메인별 현재 SOT, 불변 이력, 완료 영수증과 `managed-report.json`을 포함한다.
기존의 비관리 경로 한계 재현도 그대로 남겨 두 경로의 차이를 검증한다.

추가로 다음을 실제 임시 파일과 패키징된 CLI에서 검증했다.

- dry-run의 무쓰기, 초기 등록의 원본 바이트 보존, 중복 기록 거절.
- 일부 파일만 바뀐 중단 상태 복구와 반복 복구의 멱등성.
- 알 수 없는 외부 수정과 **완료 후 외부 되돌리기**의 덮어쓰기 거절.
- 미완료 쓰기를 capture로 숨기는 행위 거절.
- 이력 digest 손상, 마지막 기록 누락, 전체 기록 누락과 살아 있는 영수증의
  불일치, 중복 정의 ID 거절.
- scope별 독립 ID, 폐기한 상세기능 인덱스, 명시적 대체 관계.
- 부모만 다시 바뀌어도 이전 부모 영향 검토를 stale로 표시.
- 동시에 쓰는 프로세스와 실행 중 잠금 소유자 거절, 종료된 소유자 해제.
- 작업공간 밖을 가리키는 junction을 따라 쓰지 않음.
- 소스 저장소 밖에 패키징한 플러그인으로 등록·상태 조회 실행.

`npm run test:journal`과 `npm run check:all`이 통과했다. 후자는 저장소
검사, 빌드, 기존 엔진·평가·호환성·패키징 회귀와 7개 브라우저 스크립트를
포함한다. 전체 검사 첫 실행에서 viewer.html 파일 open 오류가 한 번
발생했으며, 파일 속성을 확인한 뒤 같은 코드로 빌드와 전체 검사를 재실행해
통과했다. 일회성 오류의 정확한 원인은 확정하지 않았고 우회 코드는 넣지 않았다.

독립 코드 검토에서는 완료 후 외부 되돌리기의 오분류, 유실 이력의
영수증 대조 누락, legacy KPI 중복 ID의 덮어쓰기를 발견했다. 각각 재현
테스트와 수정 후 재검토를 통과했으며, 해당 범위의 중요한 잔여 문제는
보고되지 않았다. 검토 범위 밖의 무결함을 보증하는 결과는 아니다.

지침 적용 확인에서는 별도 에이전트가 새 지침과 가상 작업공간만 읽고,
정책 문구 차이·병합 잔여 검토·폐기 이유·대체 ID 미기록·ID 재사용 금지를
찾았다. 이는 한 번의 AI 참조 적용 확인이며 사람의 인수인계 실측이나
지침 개선의 인과적 효과 검증은 아니다. 초기 등록도 sequence 1이므로
레코드 번호와 실제 변경 건수를 구분한다.

## 호환성 및 운영 경계

- 배포 전 후보이며 버전은 0.17.2로 유지했다. 설치 캐시·실제 서비스
  산출물·기존 데모를 전환하지 않았고 커밋·푸시·배포하지 않았다.
- 저널은 선택적으로 등록한 정규 작업공간에만 적용된다. 플러그인 지침에
  등록된 작업공간의 지원되는 수정 경로를 연결했다. 기존 직접 CLI와
  외부 편집기는 보호를 우회할 수 있어, 이후 drift 확인·capture가 필요하다.
- 이 변경은 SOT 기반 추적이다. 서비스 코드 저장소를 자동 감시하거나,
  코드를 기획에 자동 동기화하는 기능을 구현한 것은 아니다.
- 동시 외부 편집기를 잠그지 못하고 다중 파일 전체 원자성·전원 장애·
  네트워크 파일시스템 내구성은 보증하지 않는다. 적용 중 외부 편집을
  중지하고 제품 폴더와 저널을 함께 백업해야 한다.
- 해시는 동일성을 확인할 뿐 승인 서명이 아니다. 등록 이전 또는 통째로
  유실된 이력은 복구하지 못한다. 저널을 자동 압축·삭제하지 않는다.
- 인수인계 요약은 CLI에서 제공하며 브라우저의 저널 UI는 이번 범위가 아니다.

## 이제 남기는 사람 판단

자동 검사와 기록은 준비됐지만 다음은 실제 근거나 사람이 필요하다.

1. 정책이 실제 서비스 요구에 맞는지, 발견된 충돌을 어떻게 해결할지.
2. 병합의 미반영 정책·KPI를 반영할지, 해당 없음으로 판정할지와 그 이유.
3. 새 담당자가 이 자료로 올바르게 인수인계할 수 있는지와 실측 시간.
4. 실제 서비스의 등록 범위·백업·보존 정책 및 릴리스 승인.

이를 대신 확정하지 않기 위해 승인 영수증 입력, 새로운 정책 관계의 SOT
계약 확정, 실제 작업공간 전환과 배포는 진행하지 않았다. 앞으로의 기계적
확장 후보가 없다는 뜻은 아니며, 이번에 합의한 자동화 범위의 후보를
검증 가능한 상태로 준비했다는 의미다.
