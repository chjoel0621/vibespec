## 배포 결정

**배포 보류.** 사용자가 지정한 조건인 “다른 신규 테스트에서도 문제없을 때 배포”를
충족하지 못했다. 새로운 18개 사례 중 16개 통과, 2개 실패가 두 번의 실행과 별도
코드 리뷰에서 재현됐다. 기존 92개 사례는 이번 재실행에서도 전부 통과했다.

별도로 실제 호스트 릴리스 게이트도 현재 런타임과 증거의 digest 불일치로 실패했다.
테스트 기대값이나 호스트 증거를 고쳐 성공으로 만들지 않았다. 이번 작업은 추가 테스트,
원인 확인, 배포 전 점검, 문서 관리이며 신규 결함의 실행 코드는 아직 수정하지 않았다.

## 기존 검사와 다른 점

기존 92개는 캠페인 동의·회의실 예약·CRM 내보내기 합성 예제의 두 문서 상태 조합이
중심이었다. 이번에는 저장소의 쇼핑·결제 트리 fixture를 사용하고, 이를 환불·분쟁의
중첩 트리와 형제 기획으로 구성해 다른 통합 경로를 검사했다. fixture 자체는 기존
자료이므로 새로 생성한 실제 서비스나 독립적인 운영 표본이라고 주장하지 않는다.

중단 검증은 저장된 intent와 전후 파일 상태를 구성한 검사이며 전원 장애 실험은 아니다.

## 발견 1: 파일 이동이 변경 요약에서 누락됨 — P2

재현: 등록된 `initiatives/payment.sot.json`을 `initiatives/archive/payment.sot.json`으로
이동한 다음 capture한다. 파일 내용과 안정 scope ID는 그대로다.

관찰: capture는 성공하고 새 스냅샷에 새 경로가 보존되지만, `history`의 최신
`changes`는 빈 배열이다. 검토 인수인계 요약에서 실제 파일 이동이 빠진다.
스냅샷 데이터가 유실된 문제로 과장해서는 안 된다.

원인: [lifecycle-journal.mjs](../../plugins/vibespec/skills/vibespec/scripts/lib/lifecycle-journal.mjs)의
변경 목록 필터가 추가 scope 또는 SOT digest 변경만 남기고 경로 변경을 고려하지 않는다.

수정 방향: 파일 경로 변경도 명시적인 변경 항목에 포함하고 이전/새 경로를 추적한다.
파일 이동만으로 내용 검토를 새로 요구할지는 별개다. 이번 테스트는 변경 요약의
가시성을 요구하며 새 내용 검토 항목을 강제하지 않는다.

## 발견 2: 부모 파일 삭제 후 내부 오류 — P2

재현: 주 문서→결제→환불 트리에서 결제 파일만 삭제하고 capture한다.

관찰: 상태 조회의 트리 검증은 부모 누락을 표시하지만, capture는
`TypeError: Cannot read properties of undefined (reading 'sot')`로 종료된다.
실패 후 원본·기존 이력 파일의 바이트는 변경되지 않았다.

원인: 같은 모듈의 부모 영향 분석에서 제거된 scope를 변경 대상으로 올린 뒤,
현재 문서 목록에 그 부모가 없는데도 `.sot`를 읽는다.

수정 방향: 누락된 부모를 명시적인 진단으로 표현하거나, 기록 전에 이해 가능한
오류로 거절한다. 이번 테스트는 두 방식 모두 허용하며 잘못된 트리를 반드시
capture하도록 요구하지 않는다. 단순히 부모 검사를 생략해 문제를 숨겨서는 안 된다.

## 배포 전 점검

- 원격 저장소의 최신 릴리스는 `v0.17.2`로 확인했다. 조회만 했고 원격 변경은 하지 않았다.
- `npm run check:host-acceptance`는 `claude-code.json`의 `pluginDigest` 불일치로 종료 코드 1이었다.
- 최종 후보의 버전·런타임을 확정한 후 Claude와 Codex의 새 full-mode 설치 세션에서
  각각 독립 산출물을 만들고, 설치된 검증기로 휴대 가능한 증거를 다시 생성해야 한다.
- 이어서 로컬 호스트 게이트와 원격 **Host acceptance release gate**를 통과한
  정확한 증거 커밋에만 태그를 생성한다. 자동 fixture 테스트는 실제 호스트 증거를 대체하지 않는다.
- 이번에는 버전 변경, 원격 push·merge·태그·릴리스 게시, 설치 캐시 교체를 하지 않았다.

## 문서 관리

사용자의 “배포하면서 항상 문서를 관리” 요구를 다음 저장소 지침에 반영했다.

- `CHANGELOG.md`: 현재 변경을 **Unreleased**에 기록하고 알려진 배포 차단 사항을 표시했다.
- `docs/releasing.md`: 릴리스마다 변경 이력, 사용·호환성·복구 안내, 검증 보고서,
  경로·문서 링크 검사, 런타임 문서 변경 시 호스트 재검증을 확인하도록 보강했다.
- `CONTRIBUTING.md`: 동작 변경과 사용자 문서·미배포 변경 이력의 동기화 원칙을 추가했다.
- `docs/development.md`, `docs/README.md`, `evaluation/lifecycle/README.md`: 신규 검증 명령과
  이력 관리 안내를 연결하고, 독립 감사가 기본 `check:all`에 포함되지 않는 점을 명시했다.

이전의 92/92 통과 보고서는 해당 범위의 사실로 보존하고, 이번 새 실패를 별도 기록했다.
검토 스킬에 따라 두 실패 기대값의 타당성을 별도로 확인했으며, 완료 전 검증 절차에
따라 최초 실행과 재실행 결과를 분리해 보존했다.
