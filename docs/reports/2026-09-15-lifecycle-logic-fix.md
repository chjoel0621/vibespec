# Lifecycle 입력 검증 수정 결과

## 결과

기존 기대값을 변경하지 않고 **92개 사례 모두 통과**했다. 수정 전의 네 가지
실패는 대체 관계 입력의 falsy 값을 빈 객체로 치환하는 한 가지 결함이었다.

| 검증 | 결과 |
| --- | --- |
| 수정 전 92개 감사 | 88 통과 / 4 실패, 종료 코드 1 |
| 추가한 회귀 테스트의 수정 전 실행 | 예상 예외 누락으로 실패, 종료 코드 1 |
| 수정 후 동일한 92개 감사 | 92 통과 / 0 실패, 종료 코드 0 |
| `npm run test:journal` | 통과, 종료 코드 0 |
| `npm run check:all` | 저장소 검사·빌드·엔진·패키징·브라우저 검사 통과, 종료 코드 0 |
| 별도 코드 리뷰 | 중요한 문제 없음, 저널 단위 테스트 독립 실행 통과 |

## 수정과 회귀 방지

[lifecycle-journal.mjs](../../plugins/vibespec/skills/vibespec/scripts/lib/lifecycle-journal.mjs)의
`intent.replacements || {}`를 `intent.replacements === undefined ? {} : intent.replacements`로
변경했다. 생략만 기본값으로 처리하고 명시적인 `false`, `0`, 빈 문자열, `null`은
기존 객체 타입 검사에서 거절한다. 배열과 문자열도 계속 거절하며, 정상적인 빈 객체와
유효한 ID 대체 관계는 기존대로 처리한다. `null`까지 기본값으로 치환하는 `??`는 사용하지 않았다.

[회귀 테스트](../../plugins/vibespec/skills/vibespec/tests/lifecycle-journal.test.mjs)에
초기 등록과 변경 없는 capture에서도 잘못된 타입을 거절하는 검사를 추가했다.
생략·`undefined`·빈 객체 허용도 확인한다. 이 파일은 기존 `test:journal`, `test`,
`check`에 포함되어 있으므로 별도 명령을 기억하지 않아도 빠른 회귀 검사가 실행된다.
92개 전체 조합 감사는 독립 실행 명령으로 유지했다.

실제 CLI 적용 검증에서 네 가지 문제 입력은 모두 종료 코드 1이었고, 기록 수는
초기 1개 그대로였다. 원본 문서 및 이력 파일의 바이트가 변경되지 않았음을 확인했다.
이전에는 같은 입력이 종료 코드 0으로 끝나며 기록 수가 2개로 늘었다.

## 범위와 한계

현재 소스 체크아웃의 수정 및 테스트 완료다. 기존 서비스 문서나 운영 데이터는
변경하지 않았고 설치된 플러그인 캐시 갱신·커밋·배포도 수행하지 않았다.

전체 검사의 통과는 서비스 기획 승인과 다르다. 기존 평가에서 명시한 의미적 검증의
표본 수 부족, 사람 검토 미완료, 비관리 경로의 알려진 한계는 그대로 남아 있다.
이번 수정은 입력 검증 결함을 해결했으며 그 제품 평가 한계를 해결했다는 뜻은 아니다.
